# HSTAR 渐进重构迁移路线图（12周）

## 1. 目标与约束

- 目标：在老程序持续维护的前提下，逐步迁移到新架构，保证数值正确性、性能和可回退性。
- 约束：迁移期间老程序仍承担生产任务；新功能需要持续并行迁移。
- 原则：先建护栏、后改内核；先迁横切能力、后迁高风险物理能力；全程可灰度、可回退。

## 2. 总体策略

- 采用 `Legacy Core + Adapter + New Core + Comparator` 的桥接结构。
- 迁移初期使用“影子运行”：老内核主跑，新模块并行跑并比对，不接管结果。
- 通过 `feature flag` 分场景切换新旧内核，禁止一次性整体替换。

## 3. 12周里程碑计划

### M1（第1-2周）：基线与质量护栏

- 目标：建立迁移可验证基础。
- 交付：
  - 基准算例集（小/中/大规模，覆盖静力、非线性、接触、温度相关典型场景）。
  - 结果比对脚本（位移、应力、残差、收敛步、耗时）。
  - CI门禁规则与失败报告模板。
- 验收：
  - 老程序在固定环境重复运行3次，结果一致。
  - 任意改动若超容差自动拦截。
- 建议容差：
  - 位移相对误差：`1e-6 ~ 1e-5`
  - 应力相对误差：`1e-4`
  - 性能回退阈值：`<= 10%`

### M2（第3-4周）：桥接层与影子运行

- 目标：不改主流程，先让新架构“并行可观测”。
- 交付：
  - `legacy_facade`：封装老内核调用入口。
  - `adapter`：旧数据结构到新接口模型的映射。
  - `comparator`：新旧结果自动对比与差异报告。
- 验收：
  - 同一输入下老内核主跑稳定。
  - 新模块影子运行完成，输出可读差异报告。
  - 生产结果仍完全由老内核决定。

### M3（第5-6周）：先迁横切模块

- 目标：迁移低风险、收益高的公共能力。
- 交付：
  - 新 `input_parser`（保留旧格式兼容）。
  - 新 `error_handling` / `error_codes`。
  - 新 `output_manager`（统一GiD/VTK输出通道）。
- 验收：
  - 历史输入可读，输出文件兼容既有后处理流程。
  - 错误链路可追踪（错误码、位置、调用链）。
  - 基线算例全部通过。

### M4（第7-8周）：统一非线性迭代驱动

- 目标：收敛重复逻辑，降低后续迁移成本。
- 交付：
  - `newton_driver` 统一流程：组装、残差、边界、求解、收敛检查。
  - 老流程适配器，先覆盖“静力 + 线弹性”路径。
- 验收：
  - 与老流程结果对齐。
  - `Fem.f90` 中重复迭代分支明显减少。
  - 关键算例收敛行为可解释。

### M5（第9-10周）：分批迁移物理能力

- 目标：按风险逐步迁移元素/材料模型。
- 交付（建议首批）：
  - 元素：`HEX8`、`TET4`
  - 材料：`Elastic`、`Mohr-Coulomb`
  - 工厂注册、状态管理和回归用例。
- 验收：
  - 典型土木算例对齐通过。
  - 收敛步偏差在可解释范围内。
  - 性能不低于基线阈值。

### M6（第11-12周）：灰度切换与双线治理固化

- 目标：实现可控生产切换。
- 交付：
  - `feature flag` 按场景切换旧/新内核。
  - 一键回退开关。
  - 迁移看板、发布与应急流程。
- 验收：
  - 至少1类生产场景切换至新内核。
  - 异常可快速回退至老内核。
  - 新功能默认进入新架构通道。

## 4. 双线维护规则（迁移期强制）

1. 新功能默认落在新接口层；紧急修老代码需同步补适配器契约测试。
2. 每个PR必须附“老跑 + 影子跑”差异报告。
3. 禁止在 `Fem.f90` 继续扩散重复迭代分支，统一收敛到 `newton_driver`。
4. 每周固定审查三项：数值偏差、性能回退、未迁移高风险点。

## 5. 本周可执行清单

1. 建立 `10-15` 个黄金算例与容差表。
2. 实现 `comparator` 原型（先比位移、反力、残差）。
3. 梳理 `Fem.f90` 重复迭代段并定义首批抽象接口。

## 6. 风险与回退策略

- 高风险点：接触、多场耦合、强非线性材料、历史状态变量一致性。
- 防护措施：影子运行先行、分场景灰度、阈值门禁、随时回退。
- 回退原则：任何生产异常优先回退，先保结果正确，再定位新模块问题。
